# CS230-The-Gaming-Room

The Gaming Room wanted to expand its game, Draw It or Lose It, from an Android application that could work across multipla platforms. The application needed to support multiple games, teams, and players while keeping names unique and allowing ony one instance of the game service. 

I think I did well explaining the design requirements and organizing the documemt so the client could understand my recommendations. I compared operating platforms and considered storage, memory, security, and how the application could grow. 

Working through the design document helped me plan the code before developing it. The UML diagram helped me understand the relationships between the classes. Having a clear plan made it easier to organize the code and use inheritance and the singleton pattern. 

If I could revise one part, I would improve my comparison of the oerpating platforms. I would add more specific examples explaining how each option would affect the client's costs, maintenance, and ability to support more users. 

I interpreted the user's needs by focusing on the required game features and the goal of supporting multiple platforms. These needs guided the class structure and platform recommendations. Considering the user's needs is important because software should solve the client's problem and be practical for the people using it. 

I approached the design by breaking the requirements into smaller parts and identifying the responsibilities of each class. I used a UML diagram and object-oriented design principles to organize the application. In future projects, I would use these same strategies, review requirements early, and get feedback throughout the design process.
